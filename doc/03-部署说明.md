# QA Mini 部署说明（docker-compose 为主）

> 版本：1.0 ｜ 关联：[01-项目设计](./01-项目设计文档.md) ｜ [02-配置说明](./02-配置说明.md) ｜ [04-101服务器部署](./04-101服务器部署说明.md)
> 172.16.30.101 的**实际部署记录**见 [04-101服务器部署说明](./04-101服务器部署说明.md)。

## 1. 方式总览

| 方式 | 适用 | 说明 |
|---|---|---|
| **docker compose（推荐）** | 服务器 / 常驻 | 见 §3，一条命令起容器，数据卷持久化，自动重启 |
| 本地 Node 直跑 | 开发 / 试用 | `npm start`（需 Node ≥ 18，建议 24；无 npm 依赖，无需 install） |
| systemd | 无 Docker 的服务器 | 见 §5 附录 |

## 2. 前置条件

- Docker Engine ≥ 20.10 且 `docker compose` 插件可用（`docker compose version`）；
- 服务器可访问后端问答服务（RAGFlow / Dify / OpenAI 兼容），
  部署后在网页「⚙ 设置」填入对应 url/api_key/chat_id；
- 规划一个空闲宿主机端口（容器内固定 8787）。

## 3. docker compose 部署（标准流程）

### 3.1 准备目录

把项目源码放到目标目录（示例：`/mnt/disk1/docker-data/qa-mini`）：

```
<mkdir 目标>/qa-mini/
├─ server.js  package.json
├─ lib/          config.js qa_runner.js sse.js
├─ public/       index.html app.js style.css
└─ docker/
   ├─ Dockerfile
   └─ docker-compose.yml
└─ data/         # 运行时生成（容器挂载卷）
```

只需上述运行文件；`tests/`、`doc/`、`data/` 不需要（`.dockerignore` 已排除）。

### 3.2 修改端口（按需）

编辑 `docker/docker-compose.yml`：

```yaml
ports:
  - "8790:8787"      # 左侧=宿主机端口（自选空闲端口），右侧固定 8787
```

### 3.3 构建并启动

```bash
cd <目标>/qa-mini/docker
docker compose up -d --build
```

compose 已默认启用 `QA_MINI_CONFIG=/app/data/config.json`：**运行时配置与
会话数据库同在数据卷**，容器重建/镜像升级均不丢配置。

### 3.4 验证

```bash
curl http://127.0.0.1:<宿主机端口>/api/health
# → {"ok":true,"uptime_s":…,"sessions":1,…}
docker compose ps          # qa-mini  Up (healthy)
docker compose logs -f     # 启动日志：推送地址 / 会话存储 / 默认会话
```

浏览器打开 `http://<服务器IP>:<宿主机端口>/`：首次自动创建「默认会话」，
进入「⚙ 设置」配置后端协议（url/api_key/chat_id），再到「会话设置」复制
asr-tool 对接片段。

## 4. 运维命令（在 docker/ 目录）

| 操作 | 命令 |
|---|---|
| 启动 / 重启 | `docker compose up -d` / `docker compose restart` |
| 停止 | `docker compose down`（数据保留在 `../data/`） |
| 查看日志 | `docker compose logs -f [--tail 200]` |
| 升级（代码更新后） | `docker compose up -d --build` |
| 健康检查 | `curl http://127.0.0.1:<端口>/api/health` |

### 数据与备份

- 持久化目录 `<目标>/qa-mini/data/`：`qa-mini.db`（SQLite，会话+历史）+
  运行时 `config.json`（默认 compose 已在该卷，见 §3.3）——**备份此目录即完成全量备份**；
- SQLite 在线备份（不锁服务）：
  `sqlite3 qa-mini.db ".backup qa-mini-$(date +%F).db"`
  （容器内也可 `docker compose exec qa-mini node -e "…node:sqlite 备份…"`）；
- 建议定时任务每日备份到异地（rsync/scp）。

### 配置后端（部署后必做）

容器首次启动生成的 `config.json` 后端地址为**空**（内置空模板，公开仓库
安全）。请用网页「⚙ 设置」或 `PUT /api/config` 填入后端真实地址
（见 [02-配置说明](./02-配置说明.md)），并验证 `GET /api/health` 与一次真实问答。

## 5. 附录：systemd（无 Docker 环境）

```ini
# /etc/systemd/system/qa-mini.service
[Unit]
Description=QA Mini
After=network.target

[Service]
WorkingDirectory=/opt/qa-mini
ExecStart=/usr/bin/node server.js
Restart=always
Environment=NODE_NO_WARNINGS=1

[Install]
WantedBy=multi-user.target
```

`systemctl daemon-reload && systemctl enable --now qa-mini`

## 6. 常见问题

| 现象 | 处理 |
|---|---|
| 端口冲突 | `ss -lntp | grep <端口>` 找占用，换 compose 左侧端口 |
| 容器反复重启 | `docker compose logs` 看堆栈；多为 data 卷权限（容器以 node 用户运行，宿主机目录需可写） |
| 问答报「请求失败: connect ECONNREFUSED」 | 后端地址在容器内不可达：config 里 127.0.0.1 指向的是**容器自身**，请写宿主机/局域网 IP 或 `host.docker.internal`（mac/win）/ 同网络服务名 |
| asr-tool 推送 401 | token 已重生成或未填对；网页「会话设置」复制最新 token |
| 浏览器打不开 | 确认监听 0.0.0.0、宿主机端口映射、防火墙放行 |
| 移动端（PWA）升级后仍是旧界面 | service worker 静态缓存：递增 `public/sw.js` 中 `CACHE` 版本号（`qa-mini-v1` → `qa-mini-v2`）后重新部署，客户端下次加载自动切版；问答 API/SSE 不受缓存影响 |

## 7. 安全建议

- 服务面向局域网；**公网暴露必须**在 compose 前加反向代理（nginx/caddy）做
  鉴权 + TLS（/api/config、/api/sessions 无鉴权）；
- `data/` 目录含 API Key 与推送 token，勿开放读取；
- 镜像建议私有仓库分发，勿把含真实 key 的 `config.json` 提交公开仓库。

# EchoAnswer 部署说明（docker-compose 为主）

> 版本：1.0 ｜ 关联：[01-项目设计](./01-项目设计文档.md) ｜ [02-配置说明](./02-配置说明.md) ｜ [04-101服务器部署](./04-101服务器部署说明.md)
> 172.16.30.101 的**实际部署记录**见 [04-101服务器部署说明](./04-101服务器部署说明.md)。

## 1. 方式总览

| 方式 | 适用 | 说明 |
|---|---|---|
| **docker compose（推荐）** | 服务器 / 常驻 | 见 §3，一条命令起容器，数据卷持久化，自动重启 |
| 本地 Node 直跑 | 开发 / 试用 | `npm start`（需 Node ≥ 18，建议 24；无 npm 依赖，无需 install） |
| systemd | 无 Docker 的服务器 | 见 §5 附录 |

## 2. 前置条件

- Docker Engine ≥ 20.10 且 `docker compose` 插件可用（`docker compose version`）；
- 服务器可访问后端问答服务（RAGFlow / Dify / OpenAI 兼容），
  部署后在网页「⚙ 设置」填入对应 url/api_key/chat_id；
- 规划一个空闲宿主机端口（容器内固定 8787）。

## 3. docker compose 部署（标准流程）

### 3.1 准备目录

把项目源码放到目标目录（示例：`/mnt/disk1/docker-data/qa-mini`）：

```
<mkdir 目标>/EchoAnswer/
├─ server.js  package.json
├─ lib/          config.js qa_runner.js sse.js …
├─ server/       routes/ services/（P2 模块化路由/服务）
├─ web/dist/     新代前端构建产物（P7 站点根；随仓库提交，COPY 入镜像）
└─ docker/
   ├─ Dockerfile
   ├─ docker-compose.yml
   └─ .dockerignore
└─ data/         # 运行时生成（容器挂载卷）
```

只需上述运行文件；`tests/`、`doc/`、`data/`、`web/` 源码与 `config.json` 不需要（`.dockerignore` 已排除）。

### 3.2 修改端口（按需）

编辑 `docker/docker-compose.yml`：

```yaml
ports:
  - "8790:8787"      # 左侧=宿主机端口（自选空闲端口），右侧固定 8787
```

### 3.3 构建并启动

```bash
cd <目标>/EchoAnswer/docker
docker compose up -d --build
```

compose 已默认启用 `ECHOANSWER_CONFIG=/app/data/config.json`：**运行时配置与
会话数据库同在数据卷**，容器重建/镜像升级均不丢配置。

### 3.4 验证

```bash
curl http://127.0.0.1:<宿主机端口>/api/health
# → {"ok":true,"uptime_s":…,"sessions":1,…}
docker compose ps          # EchoAnswer  Up (healthy)
docker compose logs -f     # 启动日志：推送地址 / 会话存储 / 默认会话
```

浏览器打开 `http://<服务器IP>:<宿主机端口>/`：首次自动创建「默认会话」，
进入「⚙ 设置」配置后端协议（url/api_key/chat_id），再到「会话设置」复制
EchoScribe 对接片段。

## 4. 运维命令（在 docker/ 目录）

| 操作 | 命令 |
|---|---|
| 启动 / 重启 | `docker compose up -d` / `docker compose restart` |
| 启动（含 https 语音入口） | `docker compose --profile tls up -d`（见 §8，tls 服务默认不启动） |
| 停止 | `docker compose down`（数据保留在 `../data/`） |
| 查看日志 | `docker compose logs -f [--tail 200]` |
| 升级（代码更新后） | `docker compose up -d --build` |
| 健康检查 | `curl http://127.0.0.1:<端口>/api/health` |

### 数据与备份

- 持久化目录 `<目标>/EchoAnswer/data/`：`echoanswer.db`（SQLite，会话+历史）+
  运行时 `config.json`（默认 compose 已在该卷，见 §3.3）——**备份此目录即完成全量备份**；
- SQLite 在线备份（不锁服务）：
  `sqlite3 echoanswer.db ".backup EchoAnswer-$(date +%F).db"`
  （容器内也可 `docker compose exec EchoAnswer node -e "…node:sqlite 备份…"`）；
- 建议定时任务每日备份到异地（rsync/scp）。

### 配置后端（部署后必做）

容器首次启动生成的 `config.json` 后端地址为**空**（内置空模板，公开仓库
安全）。请用网页「⚙ 设置」或 `PUT /api/config` 填入后端真实地址
（见 [02-配置说明](./02-配置说明.md)），并验证 `GET /api/health` 与一次真实问答。

## 5. 附录：systemd（无 Docker 环境）

```ini
# /etc/systemd/system/echoanswer.service
[Unit]
Description=EchoAnswer
After=network.target

[Service]
WorkingDirectory=/opt/echoanswer
ExecStart=/usr/bin/node server.js
Restart=always
Environment=NODE_NO_WARNINGS=1

[Install]
WantedBy=multi-user.target
```

`systemctl daemon-reload && systemctl enable --now EchoAnswer`

## 6. 常见问题

| 现象 | 处理 |
|---|---|
| 端口冲突 | `ss -lntp | grep <端口>` 找占用，换 compose 左侧端口 |
| 容器反复重启 | `docker compose logs` 看堆栈；多为 data 卷权限（容器以 node 用户运行，宿主机目录需可写） |
| 问答报「请求失败: connect ECONNREFUSED」 | 后端地址在容器内不可达：config 里 127.0.0.1 指向的是**容器自身**，请写宿主机/局域网 IP 或 `host.docker.internal`（mac/win）/ 同网络服务名 |
| EchoScribe 推送 401 | token 已重生成或未填对；网页「会话设置」复制最新 token |
| EchoScribe 持续推流 403 | 目标会话未勾选「启用电脑输出音频接收」（会话设置抽屉）；token 须为**该会话**的推送 token |
| 推流中途断流（帧不入账 / 流秒关） | 用 tls sidecar 时确认：①镜像含 `location = /api/audio/stream` 专用配置；②服务器为「收完整体再回 200」语义（nginx 在上游响应后截断 in-flight body，提前 200 = 后续帧全丢）；直连 http 入口无 ② 问题 |
| 浏览器打不开 | 确认监听 0.0.0.0、宿主机端口映射、防火墙放行 |
| 移动端（PWA）升级后仍是旧界面 | 新前端 SW 由 workbox 每次构建自动生成（autoUpdate：部署新镜像后客户端下次加载自动切版，无需手动递增版本号）；`/api/*`（含 SSE）永不进 SW 缓存 |
| 想开启管理密码 / 访问码 | URL 进 `/admin` 管理台：管理密码未初始化时显示首启「设置管理密码」表单（输入即初始化，4-64 位）；「系统设置」页签关闭匿名访问、「访问码」页签生成 6 位码（默认 8h、可延期/一键失效）。权限模型见 doc01 §3.4，字段见 doc02 §7 |

## 7. 安全建议

- 服务面向局域网；**公网暴露必须**在 compose 前加反向代理（nginx/caddy）做
  鉴权 + TLS。应用内置访问控制（doc01 §3.4）：/admin 管理密码 + 可选访问码门禁，
  管理接口（/api/config、会话 CRUD）已强制鉴权（需先设置管理密码）；
- `data/` 目录含 API Key 与推送 token，勿开放读取；
- 镜像建议私有仓库分发，勿把含真实 key 的 `config.json` 提交公开仓库。

## 8. 语音输入 https 入口（可选，compose `tls` profile）

网页「🎤 语音」按钮依赖浏览器麦克风，**麦克风仅允许在安全上下文使用**：
`http://<服务器IP>` 属非安全上下文（浏览器禁止录音，按钮禁用并 tooltip 说明），
`http://127.0.0.1/localhost` 或 **https** 可用。`docker/docker-compose.yml` 内置
可选 `echoanswer-tls`（nginx:alpine 反向代理 sidecar，**`profiles: ["tls"]` 门控，
默认 `docker compose up -d` 不启动**，不影响现有 http 入口）：

```yaml
# docker/docker-compose.yml（内置片段）
  echoanswer-tls:
    image: nginx:alpine
    profiles: ["tls"]               # 启用：docker compose --profile tls up -d
    ports:
      - "8443:443"                   # 宿主机 8443（可按需改）
    environment:
      TLS_SAN: "IP:172.16.30.101,IP:127.0.0.1,DNS:localhost"   # 证书 SAN，按实际 IP 改
    volumes:
      - ../data/echoanswer-tls:/certs        # 自签证书（首次自动生成并持久化，随 data/ 一起备份）
      - ./tls/nginx.conf:/etc/nginx/conf.d/default.conf:ro
    depends_on: [EchoAnswer]
```

- **客户端 IP / 可信代理（P8.85）**：sidecar 已透传 `X-Forwarded-For`（真实客户端 IP）；启用 sidecar 后须把
  **sidecar 容器 IP**（compose 网络内，`docker network inspect <网络名>` 查 `echoanswer-tls` 的 IPAddress）
  加入 `security.trusted_proxies`（`PUT /api/config` 或 config.json），否则审计 / 凭证 / 封禁 IP 全部记为
  sidecar 容器地址。非可信对端的 XFF 不被采信（防伪造），直连入口行为不受影响。
- **frp 公网入口（Proxy Protocol，101 实测 2026-10-09）**：站点经 frp（frps + frpc）暴露公网时，
  frpc → 本地链路的源地址会被改写（走 docker-proxy 端口映射 `127.0.0.1:8791` 时 sidecar 只见
  网关 172.21.0.1，且无 XFF），真实客户端 IP 丢失。对策：frpc **直连 sidecar 容器 IP:8443**
  （本文件内置 `listen 8443 ssl proxy_protocol;` 专用口），frpc 该 proxy 配置
  `transport.proxyProtocolVersion = "v1"`（**frp ≥0.56 特性**；0.52.3 无此能力，配置键
  `frpc verify` 报 unknown field）：

  ```toml
  [[proxies]]
  name = "web-8791"
  type = "tcp"
  localIP = "172.21.0.3"          # sidecar 容器 IP（docker network inspect）
  localPort = 8443                 # proxy_protocol 专用口
  remotePort = 19004               # frps 公网端口
  transport.proxyProtocolVersion = "v1"
  ```

  生效链：PROXY 头真实客户端 IP → **8443 专用 server 块**取 `$proxy_protocol_addr` 写入
  `X-Forwarded-For` / `X-Real-IP` → 应用侧（sidecar 容器 IP 已在 `trusted_proxies`，P8.85 ipOf
  采信 XFF 链第一个不可信跳）正确落审计。
  **nginx 变量口径（101 实测 nginx 1.27.5，务必注意）**：HTTP 模块下 PROXY 头客户端地址在
  `$proxy_protocol_addr`（`$proxy_protocol_server_addr` = 头内 dst），`$remote_addr` **恒为
  socket 对端**（frpc 拨号源 = 101 网关 172.21.0.1）——XFF 若取 `$proxy_add_x_forwarded_for`
  会把网关地址记成客户端 IP。故本文件拆为两个 server 块：443（非 PROXY 链路，XFF 用
  `$proxy_add_x_forwarded_for`，源地址由内核 DNAT 保留）与 8443（PROXY 链路，XFF 用
  `$proxy_protocol_addr`）。**frps 须同 ≥0.56**：frps 旧版不向 frpc 提供客户端地址，
  frpc 把头写成 `PROXY TCP4 127.0.0.1 127.0.0.1 …`（101 抓包实证）——frps 未升级前 frpc 保持
  指向原 8791 端口（链路可用，IP 记网关地址），frps 升级后改回 8443 即得真实 IP。
  8443 口只接受带 PROXY 头的连接（无头连接被 nginx 直接断开，可防公网直连探测）。
  **改 nginx.conf 的注意事项（101 实测坑）**：`./tls/nginx.conf` 是 bind mount，
  `sed -i` 替换文件 inode 后容器仍读旧文件（nginx -t/reload 均「成功」但不生效）——
  须覆盖写 `cat 新文件 > nginx.conf`（同 inode 即时生效）；已被 sed -i 替换过的须
  `docker compose up -d --force-recreate echoanswer-tls` 重建容器重新绑定。
- **自签证书**：sidecar entrypoint（`docker/tls/entrypoint.sh`）首次启动用
  openssl 生成 10 年自签证书（CN=EchoAnswer，SAN 取 `TLS_SAN` 环境变量）；服务器 IP
  变化时改 `TLS_SAN` 并删 `data/echoanswer-tls/` 内证书重发即可（也可 openssl 自行生成后
  放入该目录，entrypoint 发现已有证书则不再生成）。
- **nginx 转发**：`proxy_pass http://EchoAnswer:8787`，`proxy_buffering off`（SSE 实时）+
  `proxy_read_timeout 300s` + `client_max_body_size 12m`（WAV 上传）+ SSE 响应头。
- **音频长连接推流**（EchoScribe 持续推流，doc01 §3.5）：`location = /api/audio/stream`
  专用配置——`proxy_request_buffering off` + `client_max_body_size 0`（nginx 默认
  会先把请求体缓冲满才转发，长连接数小时的音频流必须关闭）+
  `proxy_read/send_timeout 3600s` + `proxy_send_lowat 0` + `chunked_transfer_encoding on`。
  **关键约束（v51 实测）**：`proxy_request_buffering off` 下，upstream 响应一旦完成，
  nginx 立即截断客户端未发完的请求体（tcpdump 复现：服务端提前回 200 → 0.5ms 后
  FIN 上游，后续帧全丢）。因此服务器侧采用「**收完整体再回 200**（带 bytes/frames
  统计）」语义（doc01 §3.5），两者必须配套；前置校验错误（401/403/409）仍即时响应
  （body 被截断无副作用）。
- **首次访问**：浏览器打开 `https://<服务器IP>:8443/` 会提示「不安全」（自签证书
  属预期）→「高级 → 继续前往」（Chrome 按浏览器 profile 记住例外）；此后麦克风
  可用，原 `http://<服务器IP>:8790` 入口不变（该入口无麦克风）。
- **离线服务器**（无法 docker hub pull）：在能联网机器 `docker pull nginx:alpine` +
  `docker save nginx:alpine -o nginx-alpine.tar` → 传到服务器 `docker load -i` 后
  再 `--profile tls up -d`（101 服务器部署即此方式，见 doc/04）。

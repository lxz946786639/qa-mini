# EchoAnswer 配置说明

> 版本：1.0 ｜ 关联：[01-项目设计文档](./01-项目设计文档.md) ｜ [03-部署说明](./03-部署说明.md)

EchoAnswer 的配置分三层：**协议级配置**（config.json，全局）、**会话级配置**
（SQLite 中每会话一行）、**运行环境**（环境变量）。管理台 `/admin`「系统设置」可改
协议级、「会话设置」（工作区 ⋯ → 设置）可改会话级，均实时生效并落盘。

## 1. 协议级配置 config.json

位置：项目根 `config.json`（可用 `ECHOANSWER_CONFIG` 环境变量改路径；官方
docker-compose 已设为 `/app/data/config.json` 落数据卷）；首次启动
自动生成（内置默认值）。网页保存 = `PUT /api/config`（深合并 + 写盘 + 广播）。

```jsonc
{
  "port": 8787,                 // 监听端口（修改后需重启服务生效）
  "host": "0.0.0.0",            // 监听地址（局域网访问保持 0.0.0.0）
  "push": {                     // ★ 仅作首次启动的迁移来源（见 §3），之后不再使用
    "token": "kaasr_…",           //   迁移为「默认会话」的 token（内置为空）
    "protocol": "ragflow",
    "continue_session": true
  },
  "protocols": {
    "openai": {
      "url": "",                  // 完整 chat completions 地址
      "api_key": "",              // Bearer（可空）
      "model": ""                                // P8.81 身份字段：智能体级必填；全局值为遗留回退
    },
    "dify": {
      "url": "",                  // 基址（自动补 /chat-messages）
      "api_key": "",              // P8.81 身份字段：智能体级必填；全局值为遗留回退
      "user": "EchoAnswer"                         // Dify user 标识
    },
    "generic": {
      "url": "",                  // 完整请求地址
      "api_key": "",                            // 可空
      "body": "{\"question\":\"{question}\"}"  // JSON 模板
    },
    "ragflow": {
      "url": "",                  // 基址
      "api_key": "",              // 必填
      "chat_id": "",              // P8.81 身份字段：智能体级必填；全局值为遗留回退
      "user": ""                  // P8.81 续：请求 user 字段（可选，留空 = 不发送；连接级，三层可配）
    }
  },
  "asr": {                        // 网页语音输入（麦克风 → 文字）所用 ASR 服务
    "url": "",                    // ASR 服务基址（OpenAI 兼容；自动补 /v1；空 = 未启用）
    "api_key": "",                // Bearer（可空，部分服务无需鉴权）
    "model": "",                  // 模型名（建议填；「测试连接」会校验其在服务模型列表中）
    "language": "",               // 语言提示（空 = 自动检测）
    "timeout": 60                 // 识别超时秒数（1-300，整数）
  },
  "audio_stream": {               // 电脑输出音频流（EchoScribe 持续推流）
    "max_buffer_s": 120,          // 每设备环形缓冲保留秒数（5-3600；32KB/s ≈ 3.8MB/120s）
    "min_capture_s": 5,           // 「识别并提问」最短截取秒数（须 ≤ max_capture_s）
    "default_capture_s": 30,      // 未指定 seconds 时的截取秒数（须在 min-max 内）
    "max_capture_s": 60           // 最长截取秒数（须 ≤ max_buffer_s）
  }
}
```

要点：

- **协议配置是「连接级全局默认」（P8.81）**：所有会话共用 url/key/user 等连接参数；
  身份级字段（ragflow.chat_id / openai.model / dify.api_key）移「智能体管理」按智能体
  必填配置（保存校验 400 指明字段），全局身份值仅作遗留回退（v8 迁移后清空）；
  会话还可携带**会话级覆盖**（`protocol_config`，见 §2）：逐字段「非空值优先」的
  三层解析 全局 ← 智能体（仅会话协议 = 智能体协议时参与）← 会话。
- 内置默认为**空模板**（公开仓库安全：代码与文档不含真实 key/token）；
  首次启动请在管理台「/admin → 系统设置 → 协议全局默认」填入后端真实地址并保存
  （落盘 config.json）。
- `port` 变更需要重启（监听已建立）；其余字段保存即生效。
- `PUT /api/config` 为**深合并**（只传改动的键即可）；非法值（port 越界、
  protocol 非法等）→ 400 不落盘。
- **`audio_stream` 块（电脑输出音频流）**：EchoScribe「持续推流」到本服务时的服务端
  缓冲与截取参数（推流协议/鉴权/流程见 01 §3.5）。仅内存缓冲，不落盘；保存即生效。
  校验：四值均为整数、`min ≤ default ≤ max`、`min ≤ max_capture`、
  `max_capture_s ≤ max_buffer_s`，违反 → 400 不落盘。
- **`asr` 块（网页语音输入）**：供网页「🎤 语音」按钮使用——浏览器录 WAV 后
  `POST /api/asr`，服务端按此配置转发 OpenAI 兼容 ASR 服务（与 EchoScribe 同源同协议）。
  `url` 为空 = 未启用（接口 400，前端按钮照常显示但送识别失败并提示）；保存即生效，
  无需重启。管理台「系统设置 → 语音输入（ASR）」可改并可**测试连接**（用当前填写值探测
  `GET {root}/health` + `GET {base}/models`，模型不在列表时给出警告）。密钥在
  `config` SSE 广播中脱敏（显示「…已设置」）。

每会话一行（sessions 表），网页「会话设置」抽屉管理：

| 字段 | 网页入口 | 说明 |
|---|---|---|
| name | 会话名称 | 侧栏显示名 |
| protocol | 协议下拉 | ragflow / openai / dify / generic |
| protocol_config | 「本会话协议配置」字段组 | 会话级协议覆盖（结构同全局 `protocols[协议]`）；非空值优先，留空 = 用全局默认；占位符只显示全局是否已配置（**不显示全局值明文**）；修改后须「测试连接」通过才能保存（见下） |
| continue_session | 「续接会话」勾选 | 语音追问携带上下文 |
| audio_remote | 「启用电脑输出音频接收」勾选（识别交互在提问框「音频」按钮，见 01 §7） | `{enabled, preferred_device}`——EchoScribe 持续推流目标开关；preferred_device 无独立 UI（内部回退：capture/listen 未指定 device 时用，失效时唯一设备流自动用之）（推流/识别流程见 01 §3.5）；enabled=false 时推流 403 |
| id | 只读 + 复制 | 8 hex，EchoScribe body 引用，**不可改** |
| token | 只读 + 复制 + 重生成 | 重生成后旧 token 立即 401，需同步 EchoScribe |
| dify_conversation_id / ragflow_session_id | 「重置会话」清空（先取消在途问答） | 后端会话上下文 |
| history | 卡片「删」可删单条 | 最近 100 条（records 表） |

操作语义：

- 新建会话：POST /api/sessions `{name?, protocol?, continue_session?, agent_id?/agent_code?}`
  （P3：管理 / 登录用户（落自身私有桶）/ 访问码主体（落自身码桶）可用，匿名 401；
  智能体缺省 = 种子智能体 industry-brain）；
- 改/删会话（P3）：PUT/DELETE /api/sessions/:id 与删记录 = 管理 或 该私有会话属主
  （他人桶 401）；详情/chat/cancel = 查看级 + 该会话可见（不可见 404）；
  reset / protocol-test / 全局重置仍仅管理；
- 会话级协议配置：PUT `{protocol_config: {协议: {字段: 值}}}`——按提交的协议
  key 整体替换该协议的覆盖（其余协议不动）；值 trim 后空字符串丢弃（= 回退上层默认：
  智能体层/全局），未知协议/字段/非字符串丢弃，`{协议: {}}` = 清除该协议全部覆盖；
  请求体 `protocol_config` 非对象 → 400。非管理视图不返回该字段（含 api_key）；
  **若变更后该会话生效的 url/api_key/chat_id（ragflow）或 url/api_key（dify）
  变化（P8.81 三层解析 全局 ← 智能体 ← 会话 逐字段判定；智能体配置变更同样触发），
  或协议切换，自动清空该会话 `dify_conversation_id`/`ragflow_session_id`**
  （旧后端会话不属于新 chat，不清空 RAGFlow 会回「Session does not belong to
  this chat!」→ 空回答；清空后下次提问自动重建）；
- **测试连接**：POST /api/sessions/:id/protocol-test（管理）`{protocol?, config?}`——
  用 全局 ← 智能体 ← 表单草稿 三层合并值（与提问取值一致）按协议探测一次后端；
  **P8.81** 新增 POST /api/admin/protocol-test（管理）`{protocol, config?, agent_code?}`
  供智能体对话框/列表「测试」：同一三层合并链 + 前置校验（无会话参与）；
  openai POST url（max_tokens=1 非流式）；dify GET 基址/parameters；
  ragflow GET 基址/chats/{chat_id}（HTTP 200 且业务码 code==0 才算通过）；
  generic 按模板 POST 一次（question=ping）。返回 `{ok, detail}`：HTTP 恒 200，
  ok=false 时 detail = 失败原因（未配置预检/HTTP 状态+后端 message 截断/
  无法连接原因），**不回显 api_key**；前端语义：草稿与已保存值不同且含非空值时
  「保存」禁用直至测试通过（全部清空回退全局无需测试）；
- 旧库升级：引入 `protocol_config` 列后首次启动自动 `ALTER TABLE` 补列（默认
  `'{}'`，数据保留）；`audio_remote` 列同法（默认 `'{}'`，解析失败回退
  `{enabled:false, preferred_device:""}`）；
- 电脑输出音频：PUT `{audio_remote: {enabled?, preferred_device?}}`——对象合并
  （enabled 须布尔、preferred_device trim 后 ≤128 字符，非法值忽略）；开关即时生效
  （推流门控与 capture/listen 设备回退按最新值）；`{audio_remote: {}}` 等价不变更；
- 全局 `PUT /api/config` 改动协议配置时：回退全局的会话（对应字段留空）生效值
  变化 → 同样自动重置其后端会话 ID（响应含 `invalidated_sessions` 计数）；
- 重生成 token：PUT `{regenerate_token: true}`；
- 重置会话：POST /api/sessions/:id/reset（先取消在途问答，再清空后端会话 ID，保留历史）；
- 删除会话：DELETE /api/sessions/:id（取消在途问答；删光自动补建「默认会话」）；
- 删单条记录：DELETE /api/sessions/:id/history/:qaId（广播 record_removed 各端同步）。

## 3. 配置迁移链（首次启动）

按顺序（仅在对应条件成立时发生一次）：

1. **v1→v2 schema 迁移**（P1，库文件存在且 `user_version < 2` 时）：旧名
   `qa-mini.db` 先重命名；升级前自动备份 → `data/backup/echoanswer.db.bak-<时间戳>`；
   单事务升级表结构（v2 列 + users/agents/agent_configs/protocol_defaults/
   system_configs/access_codes/audit_logs，见 01 §6）并置 `user_version = 2`；
   播种 admin 用户（初始密码 = `ECHOANSWER_ADMIN_PASSWORD` 或 config
   `security.admin_password`，scrypt 哈希入库）、agent `industry-brain`、协议默认值、
   系统配置、访问码（allow_anonymous 时含 ANON 匿名共享桶码）；存量会话归属回填
   管理员私有桶（未建管理员时留空，首次 admin 初始化时补回填）；config.json 明文
   管理密码清空（先备份 `config.json.bak-<时间戳>`，DB `users` 表为权威）。
1b. **v2→v3 访问控制补列**（P8.8，库 `user_version = 2` 时）：同一备份红线，单事务
   补 agents 三列 `allow_anon/allow_code/allow_user`（NOT NULL DEFAULT 1，存量智能体
   保持全放行 = 行为不变），置 `user_version = 3`。
1c. **v3→v4 管理员新建会话回填**（P8.10，库 `user_version = 3` 时）：同一备份红线，
   单事务、无 DDL：`access_mode='shared'` 且 `user_id` = 管理员用户 且
   `created_at` ≥ 2026-10-05（P3 提交日 = 重构切换点）的会话 → `access_mode='user'`
   （管理员私有桶）；重构前存量（早于切换点）与 `user_id` 为空的行不动；全新安装
   无匹配行（no-op），置 `user_version = 4`；全新安装直接建 v4。
1d. **v4→v5 审计补列**（P8.29，库 `user_version = 4` 时）：audit_logs 补 `user_agent`
   （设备浏览器指纹），置 `user_version = 5`。
1e. **v5→v6 权限范围补列**（P8.40，库 `user_version = 5` 时）：users/access_codes
   补 `agent_scope`（agent id JSON 数组，空 = 全部），置 `user_version = 6`。
1f. **v6→v7 IP 封禁表**（P8.49，库 `user_version = 6` 时）：`CREATE TABLE IF NOT
   EXISTS ip_bans`（幂等；ip 主键 / reason / created_by / created_at / expires_at，
   NULL = 永久），置 `user_version = 7`；全新安装直接建 v7。
1g. **v7→v8 身份字段迁移**（P8.81，库 `user_version = 7` 时）：无 DDL：逐智能体，对应
   协议身份级字段（ragflow.chat_id / openai.model / dify.api_key）为空且旧全局值
   （protocol_defaults 行，其次 config.json）非空 → 回填该智能体 agent_configs；随后
   清空 protocol_defaults 对应字段（DB 权威源），config.json 文件同步清空身份字段
   （先备份 `config.json.bak-<时间戳>`）；连接级字段（url/user 等）保留；生效配置不变
   → 不清空后端会话 ID，置 `user_version = 8`；全新安装直接建 v8。
2. **旧 JSON 迁移**：库为空且存在 `data/sessions.json` → 全量导入 SQLite，
   旧文件归档为 `sessions.json.bak-<时间戳>`；
3. **默认会话**：库仍为空 → 用 `config.push` 的 token/protocol/continue_session
   创建「默认会话」（旧 EchoScribe 配置零改动）；
4. 之后 `config.push` 不再参与任何逻辑。

## 4. EchoScribe 对接配置（对方 echoscribe.toml）

EchoScribe「第三方接口」改为**推送模式**（网页「会话设置」中可直接复制片段与
body 值）：

> EchoScribe v1.0.0 起由 asr-live 改名：配置文件由 `config.toml` 改为 `echoscribe.toml`
>（旧文件首次运行自动迁移；`[third_party]` 表与字段不变，下方片段照旧直接粘贴）。

```toml
[third_party]
url = 'http://<本机IP>:8787/api/push'
body = '{"token":"kaasr_…","session_id":"8b14dd80"}'
auto_send = true
qa_enabled = false        # 必须推送模式
```

- 请求体 = `{**body, "text": 识别文本}`；token 定位会话、session_id 校验一致性；
- 默认 202 异步返回；需 EchoScribe 同步拿答案用 `POST /api/push?sync=true`
  （阻塞至完成，上限 28s，返回 `{ok, answer, detail}`）。

### 4.1 持续推流模式（电脑输出音频 → EchoAnswer）

EchoScribe 新增「持续推流」：捕获指定**输出设备**的 WASAPI 回环音频（48kHz float32
→ 16kHz 16-bit 单声道），按 200ms 帧 `[u32BE len][Deflate(PCM)]` 以长连接
chunked POST 持续推到 `POST {本服务地址}/api/audio/stream`（复用既有端口/
TLS sidecar，不新增端口）。

```toml
[qa_mini_stream]
url = 'http://<EchoAnswer地址>/api/audio/stream'   # https 时填 sidecar 地址
token = 'kaasr_…'          # 目标会话的推送 token（网页「会话设置」复制）
device = '扬声器 (ToDesk Virtual Audio)'  # 留空 = 默认输出设备
```

- 前置条件：目标会话在网页「会话设置」勾选「启用电脑输出音频接收」，否则 403；
- 响应语义：前置校验错误（401/403/409）即时返回；成功路径在**流结束**（客户端
  结束 chunked 体）后回 `200 {ok, stream:"stopped", bytes, frames}`——nginx 在上游
  响应完成后会截断 in-flight body，无法提前回 200（详见 doc/03 §8）；推流实时状态
  用 SSE `audio_stream` 事件或 `GET /api/audio/stream?token=` 观测；
- 推流中可在网页「会话设置」点「🎧 识别并提问」截取最近 N 秒 → ASR（用 `asr`
  块配置）→ 自动作为该会话提问（source = remote_audio）；
- 多设备：同一会话可收多个设备流（≤8），「默认设备」下拉指定识别目标；
- 断线自动重连（2s 起步指数退避）；EchoAnswer 侧重启不丢已推数据（推流端重连即恢复）。

## 5. 环境变量

| 变量 | 默认 | 说明 |
|---|---|---|
| `ECHOANSWER_CONFIG` | `<项目根>/config.json` | 协议配置文件路径 |
| `ECHOANSWER_DATA_DIR` | `<项目根>/data` | 会话存储目录（echoanswer.db 所在；测试用它隔离） |

## 7. 访问控制（config.json 的 security 块）

| 字段 | 默认 | 说明 |
|---|---|---|
| `security.admin_password` | `""`（空） | 管理密码（**v2 后为引导通道**）。**空 = 管理未启用**（管理接口不鉴权，旧行为）；首次 `POST /api/admin/login`（或浏览器 `/admin` 登录页）输入即**初始化**（4-64 位，scrypt 哈希入 DB `users` 表）；v2 迁移时本字段明文自动清空（先备份 config.json，见 §3）；之后管理台「系统设置」/「用户管理（重置密码）」修改走 `PUT /api/config` 双写（config.json 镜像 + DB 权威） |
| `security.allow_anonymous` | `true` | **P8.44 起失效（字段保留兼容，不再生效）**：首屏与匿名问答恒公开；历史语义 false = 打开应用需 6 位访问码 |
| `security.access_codes` | `[]` | 访问码列表 `[{code, expires_at, created_at}]`：6 位数字（自定义或随机）；**可多个，每个码独立有效时长**（默认 8h，0.5-720h；批量随机 1-10 个）；一键失效 = DELETE（已发 token 同步吊销） |
| `security.auto_ban` | `{enabled: true, login_fails: 10, qa_per_min: 20, ban_minutes: 60}` | **P8.49 自动 IP 封禁**：`enabled` 布尔（true = 启用）；`login_fails` 正整数 = 同一安全维度 IP 10 分钟内登录失败达阈值即自动封禁（缺省 10）；`qa_per_min` 正整数 = 同一 IP 1 分钟提问达阈值即自动封禁（缺省 20）；`ban_minutes` 非负整数 = 自动封禁时长（分钟，0 = 永久，缺省 60）。`PUT /api/config` 修改实时生效（校验：enabled 布尔 / 其余非负整数）；爆破与高频的内存计数重启清零，DB 封禁记录持久。管理端「安全监控」提供手动封禁（1h/24h/7d/永久）与解除 |

权限模型（管理/查看/公开三级端点表）见 doc01 §3.4。注意：

- 管理 token 走 `X-Admin-Token` 请求头；访问 token 走 `?access=` 查询参数；
  **管理 token 也可走 `?access=`**（查看级端点两者皆认）——/admin 页的 SSE
  （EventSource 无法自定义请求头）与查看级 XHR 靠它携带管理凭证：管理端一次登录
  即可用全部展示功能，无需再输访问码
  （SSE EventSource 无法自定义请求头，故用查询参数）。
- EchoScribe 推送**只需会话推送 token**（token 本身即凭证，48 位高熵随机值，
  持有即授权）；访问码失效/换码不影响推送（P8.44：会话列表/历史/SSE 等查看类端点
  匿名恒放行；显式携带的凭证无效仍 403）。
- 服务端 token：遗留 token（管理 12h / 访问 24h）仅存内存（重启失效，保留一个版本）；
  **P3 cookie 会话落 DB `auth_sessions`**（token 哈希存储，重启存活，可吊销：登出 /
  停用用户 / 失效或过期访问码时对应会话全吊销）。访问码列表持久化在 DB
  `access_codes` 表（config.json `security.access_codes` 为每次码变更时重建的内存
  镜像，排除 ANON，随配置备份留档）。
- **P3 主体与桶**：请求主体优先级 `ea_sid` cookie → 遗留 `X-Admin-Token`/`?admin=`
  → 遗留 `?access=`/`x-access-token` → 匿名；会话可见性按桶（shared 全可见 /
  user 属主+管理 / code 持有者+管理），详见 01 §3.4。

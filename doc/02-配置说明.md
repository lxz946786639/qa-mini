# QA Mini 配置说明

> 版本：1.0 ｜ 关联：[01-项目设计文档](./01-项目设计文档.md) ｜ [03-部署说明](./03-部署说明.md)

QA Mini 的配置分三层：**协议级配置**（config.json，全局）、**会话级配置**
（SQLite 中每会话一行）、**运行环境**（环境变量）。网页「⚙ 设置」可改协议级、
「会话设置」可改会话级，均实时生效并落盘。

## 1. 协议级配置 config.json

位置：项目根 `config.json`（可用 `QA_MINI_CONFIG` 环境变量改路径；官方
docker-compose 已设为 `/app/data/config.json` 落数据卷）；首次启动
自动生成（内置默认值）。网页保存 = `PUT /api/config`（深合并 + 写盘 + 广播）。

```jsonc
{
  "port": 8787,                 // 监听端口（修改后需重启服务生效）
  "host": "0.0.0.0",            // 监听地址（局域网访问保持 0.0.0.0）
  "push": {                     // ★ 仅作首次启动的迁移来源（见 §3），之后不再使用
    "token": "kaasr_…",           //   迁移为「默认会话」的 token（内置为空）
    "protocol": "ragflow",
    "continue_session": true
  },
  "protocols": {
    "openai": {
      "url": "",                  // 完整 chat completions 地址
      "api_key": "",              // Bearer（可空）
      "model": ""                                // 空则不发送 model 字段
    },
    "dify": {
      "url": "",                  // 基址（自动补 /chat-messages）
      "api_key": "",              // 必填（Bearer）
      "user": "qa-mini"                         // Dify user 标识
    },
    "generic": {
      "url": "",                  // 完整请求地址
      "api_key": "",                            // 可空
      "body": "{\"question\":\"{question}\"}"  // JSON 模板
    },
    "ragflow": {
      "url": "",                  // 基址
      "api_key": "",              // 必填
      "chat_id": ""               // 必填（聊天助手 ID）
    }
  }
}
```

要点：

- **协议配置是全局的**：所有会话共用 url/key/chat_id；会话只决定「走哪个协议」。
- 内置默认为**空模板**（公开仓库安全：代码与文档不含真实 key/token）；
  首次启动请在网页「⚙ 设置」填入后端真实地址并保存（落盘 config.json）。
- `port` 变更需要重启（监听已建立）；其余字段保存即生效。
- `PUT /api/config` 为**深合并**（只传改动的键即可）；非法值（port 越界、
  protocol 非法等）→ 400 且不落盘。

## 2. 会话级配置（SQLite data/qa-mini.db）

每会话一行（sessions 表），网页「会话设置」抽屉管理：

| 字段 | 网页入口 | 说明 |
|---|---|---|
| name | 会话名称 | 侧栏显示名 |
| protocol | 协议下拉 | ragflow / openai / dify / generic |
| continue_session | 「续接会话」勾选 | 语音追问携带上下文 |
| id | 只读 + 复制 | 8 hex，asr-tool body 引用，**不可改** |
| token | 只读 + 复制 + 重生成 | 重生成后旧 token 立即 401，需同步 asr-tool |
| dify_conversation_id / ragflow_session_id | 「重置会话」清空 | 后端会话上下文 |
| history | 卡片 🗑 可删单条 | 最近 100 条（records 表） |

操作语义：

- 新建会话：POST /api/sessions `{name?, protocol?, continue_session?}`；
- 重生成 token：PUT `{regenerate_token: true}`；
- 重置会话：POST /api/sessions/:id/reset（清空后端会话 ID，保留历史）；
- 删除会话：DELETE /api/sessions/:id（取消在途问答；删光自动补建「默认会话」）；
- 删单条记录：DELETE /api/sessions/:id/history/:qaId（广播 record_removed 各端同步）。

## 3. 配置迁移链（首次启动）

按顺序（仅在对应条件成立时发生一次）：

1. **旧 JSON 迁移**：库为空且存在 `data/sessions.json` → 全量导入 SQLite，
   旧文件归档为 `sessions.json.bak-<时间戳>`；
2. **默认会话**：库仍为空 → 用 `config.push` 的 token/protocol/continue_session
   创建「默认会话」（旧 asr-tool 配置零改动）；
3. 之后 `config.push` 不再参与任何逻辑。

## 4. asr-tool 对接配置（对方 config.toml）

asr-tool「第三方接口」改为**推送模式**（网页「会话设置」中可直接复制片段与
body 值）：

```toml
[third_party]
url = 'http://<本机IP>:8787/api/push'
body = '{"token":"kaasr_…","session_id":"8b14dd80"}'
auto_send = true
qa_enabled = false        # 必须推送模式
```

- 请求体 = `{**body, "text": 识别文本}`；token 定位会话、session_id 校验一致性；
- 默认 202 异步返回；需 asr-tool 同步拿答案用 `POST /api/push?sync=true`
  （阻塞至完成，上限 28s，返回 `{ok, answer, detail}`）。

## 5. 环境变量

| 变量 | 默认 | 说明 |
|---|---|---|
| `QA_MINI_CONFIG` | `<项目根>/config.json` | 协议配置文件路径 |
| `QA_MINI_DATA_DIR` | `<项目根>/data` | 会话存储目录（qa-mini.db 所在；测试用它隔离） |
| `QA_MINI_CONNECT_TIMEOUT_MS` | 10000 | 后端连接超时（测试缩短） |
| `QA_MINI_IDLE_TIMEOUT_MS` | 60000 | SSE 块间空闲超时（测试缩短） |
| `NODE_NO_WARNINGS` | — | 容器内建议 1（屏蔽 node:sqlite 实验性警告） |

## 6. 浏览器本地配置（localStorage，前端自管）

| 键 | 说明 |
|---|---|
| `qa-mini-theme` | `dark` / `light` 主题 |
| `qa-mini-font` | 字号模式（default 15px / large 18px / custom 12–28px） |
| `qa-mini-width` | 内容宽度模式（narrow 860px / wide 1180px / full 铺满主容器） |
| `qa-mini-sidebar` | 桌面侧栏收起状态 |
| `qa-mini-admin` / `qa-mini-access` | 管理/访问鉴权 token（带 expires_at，过期自动失效） |

## 7. 访问控制（config.json 的 security 块）

| 字段 | 默认 | 说明 |
|---|---|---|
| `security.admin_password` | `""`（空） | 管理密码。**空 = 管理未启用**（管理接口不鉴权，旧行为）；首次 `POST /api/admin/login`（或浏览器 `/admin` 登录页）输入即**初始化**（4-64 位）；之后 ⚙ 设置 → 安全 可修改 |
| `security.allow_anonymous` | `true` | 是否开放匿名访问。false = 打开应用需 6 位访问码 |
| `security.access_codes` | `[]` | 访问码列表 `[{code, expires_at, created_at}]`：6 位数字（自定义或随机）；**可多个，每个码独立有效时长**（默认 8h，0.5-720h；批量随机 1-10 个）；一键失效 = DELETE（已发 token 同步吊销） |

相关端点：

| 端点 | 说明 |
|---|---|
| `GET /api/status` | 公开：`{ok, allow_anonymous, admin_set}`（无敏感信息） |
| `POST /api/admin/login` | `{password}` → 管理 token（12h）。未设密码时输入即初始化；错密码 401；限流 429（10 次失败/10 分钟/IP） |
| `POST /api/access/login` | `{code}` → 访问 token（24h，且不超过码有效期）；无效/过期 401；匿名开放时直接 200 `{anonymous:true}` |
| `POST /api/admin/access-codes` | `{code?, hours?, count?}` → 201 生成（code 省略 = 随机；count 1-10 批量随机，每个码独立 hours）；响应 `{entries: [...]}` |
| `POST /api/admin/access-codes/:code/renew` | `{hours?}` → 该码到期时间后移 hours（默认 8h，取当前到期与现在较大者起算） |
| `DELETE /api/admin/access-codes/:code` | 一键失效（已发 token 同步吊销） |
| `DELETE /api/admin/access-codes/expired` | 清理全部已过期码 → `{removed: n}` |

权限模型（管理/查看/公开三级端点表）见 doc01 §3.4。注意：

- 管理 token 走 `X-Admin-Token` 请求头；访问 token 走 `?access=` 查询参数
  （SSE EventSource 无法自定义请求头，故用查询参数）。
- 开启访问码（allow_anonymous=false）后，asr-tool 推送需在请求体附带
  `access`（访问 token），否则 403。
- 服务端 token 仅存内存：重启后管理/访问需重新登录；访问码列表持久化在
  config.json（随配置备份）。

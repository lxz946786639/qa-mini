> 关联文档：[02-配置说明](./02-配置说明.md) ｜ [03-部署说明](./03-部署说明.md) ｜ [04-101服务器部署说明](./04-101服务器部署说明.md)

## 1. 项目定位

EchoAnswer（回响答，原名 QA Mini；v58 整体改名 2026-10-05）是一个 **Web 端语音问答展示**
服务：接收 EchoScribe（回响笔）（原名 asr-live，dev 分支）**推送模式** 发来的语音识别文本，
以该文本为提问，调用四种问答协议之一（openai / dify / generic / ragflow），在浏览器中
**实时流式** 展示 Markdown 答案。两产品分工：EchoScribe（回响笔）采集转写 → EchoAnswer（回响答）问答展示。

核心设计目标：

| 目标 | 方案 |
|---|---|
| 零依赖 | Node 内置模块（http / fs / crypto / node:sqlite）+ 原生 JS 前端，无 npm 包、无构建步骤 |
| 协议行为一致 | 四种协议的请求/解析/容错逻辑 1:1 移植自 EchoScribe |
| 多会话隔离 | 每会话独立 token / 会话ID / 协议 / 后端会话状态 / 历史 |
| 多端实时同步 | 单一 SSE 广播通道，事件均带 session_id |
| 开箱即用 | 内置默认配置（本机 RAGFlow），首次启动自动建库、自动建默认会话 |

## 3. 会话模型（多会话核心）

### 3.1 数据模型

每会话（sessions 表一行 + 内存对象）：

| 字段 | 说明 |
|---|---|
| id | 8 位 hex，创建时生成，**不可变**（EchoScribe body 里引用它） |
| name | 显示名（可改） |
| token | `kaasr_` + 48 hex 推送令牌（可重生成，旧 token 立即失效） |
| protocol | `ragflow` / `openai` / `dify` / `generic`（会话级选择） |
| continue_session | 是否续接后端会话（语音追问带上下文） |
| protocol_config | 会话级协议覆盖 `{ [协议]: { 字段: 值 } }`（结构同全局 `protocols[协议]`；同名**非空值**优先，空值回退全局默认） |
| audio_remote | `{ enabled: bool, preferred_device: string }`——电脑输出音频接收开关与默认设备（EchoScribe「持续推流」目标；见 §3.5） |
| dify_conversation_id | Dify 多轮 conversation_id（重置时清空；重置先取消在途问答） |
| ragflow_session_id | RAGFlow 会话 ID（无则先建会话；重置时清空；重置先取消在途问答） |
| created_at / updated_at | ISO 时间（updated_at 在提问/完成/重置/删记录时刷新，即「最新对话时间」） |
| history | 最近 **100** 条问答（新→旧环形缓冲，records 表持久化） |
| user_id / agent_id | v2 归属：P3 按 用户 × 智能体 / 码 × 智能体 分桶；存量会话（shared 桶）保留 user_id = 管理员（未建时空）、agent_id = 种子智能体 `industry-brain` |
| access_mode / access_code_id | 会话桶模式：`shared`（默认，存量 + 管理/匿名创建；所有查看级主体可见，保留「访问码=共享会话」遗留语义）/ `user`（用户私有桶，属主+admin 可见）/ `code`（访问码桶，该码持有者+admin 可见）；P3 首启把存量 'user' 行一次性回填 'shared'（幂等）；`ANON` = 匿名共享桶特殊码 |

不变式：

- **至少 1 个会话**：删除最后一个会话时自动补建「默认会话」。
- 首次启动且库为空：迁移 config.json `push.token` 创建「默认会话」
  （旧 EchoScribe 配置零改动）。
- 再之前（无库）：若存在旧 `data/sessions.json`，一次性导入 SQLite 并归档为
  `sessions.json.bak-<时间戳>`。
- **列表按最新对话时间倒序**：`GET /api/sessions` 与 SSE `sessions` 广播均按
  `updated_at` 降序（同时间按创建时间降序）——最近对话的会话排最前。
- **桶归属（P3）**：存量会话（含 P2 管理员私有桶导入）一次性回填共享桶
  （access_mode='user' → 'shared'，user_id=管理员、agent_id=industry-brain；
  system_configs 标记幂等；未建管理员时 user_id 留空，首次管理员初始化时批量
  回填）——旧「访问码 = 共享会话」语义由 shared 桶保留：所有查看级主体
  （匿名/码/用户/管理）可见、可问 shared 会话。新建会话按主体落桶：user →
  私有桶 (user_id, agent_id)；访问码主体 → 码桶 (access_code_id, agent_id)；
  管理/匿名 → shared 桶。

### 3.2 定位与校验（/api/push）

1. `token` → 会话（未知 → **401**）；
2. 请求体带 `session_id` 时必须等于该会话 id（否则 **400**，防 token 复制错配）；
3. 只带 token（不带 session_id）兼容旧行为；
4. `text` 非空（否则 400）。

### 3.3 多浏览器同步

前端无轮询：EventSource 连 `/api/events`。服务器对每个客户端广播全部 QA 事件
（均带 `session_id`）；前端只渲染当前会话的 qa_start/delta/done，其余事件用于
刷新侧栏（sessions）与移除卡片（record_removed）等。切会话时
GET /api/sessions/:id 拉历史 + 在途问答，重建卡片。
另有 `audio_stream` 事件（`{session_id, device, state: started/data/stopped, bytes?}`，
data 按 1s 节流）通知电脑输出音频推流状态（见 §3.5）：前端据此在会话列表打
「🎧N」角标并实时刷新会话抽屉的设备列表。

### 3.4 访问控制（管理密码 + 访问码）

两级权限，均可选（默认 = 旧行为全开放）：

| 级别 | 开关 | 效果 |
|---|---|---|
| 管理 | `security.admin_password` | 空 = 管理未启用（管理接口不鉴权，旧行为）；设置后管理接口强制登录鉴权 |
| 访问 | `security.allow_anonymous` | true = 匿名可看可问（旧行为）；false = 需 6 位访问码进入 |

- **管理密码**：首次 `POST /api/admin/login`（或浏览器 `/admin` 登录页）输入的密码
  即**初始化**（4-64 位）；之后校验登录，可在设置中修改（`security.admin_password`）。
  管理 token 有效期 12h，仅存内存（重启需重新登录）。
- **访问码**：6 位数字，可自定义或随机生成；**可生成多个，每个码独立有效时长**
  （默认 8h，0.5-720h；批量随机 1-10 个）；存 `security.access_codes`（config.json
  持久化）；支持**单个延期**（renew，到期时间后移）、**一键失效**（删除 + 已发 token
  立即吊销）、**清理全部过期码**。访问 token 有效 24h（且不超过码自身有效期）。
- **登录限流**：10 次失败/10 分钟/IP → 429；密码/码比对走 timingSafeEqual（防时序侧信道）。
- **v2 数据层（P2 双轨）**：管理密码存 DB `users` 表（scrypt `s1:` 哈希，
  `lib/auth.js`；config.json `security.admin_password` 仅为引导通道，迁移后自动
  清空）；访问码存 DB `access_codes` 表（config.json `security.access_codes` 为
  每次变更重建的内存镜像，排除 ANON）；遗留令牌仍仅存内存（管理 12h / 访问 24h，
  保留一个版本）；限流 = 10 次失败/10 分钟/IP（内存）。
- **P3 主体（principal）模型（多用户隔离核心）**：每个请求解析为主体，优先级
  `ea_sid` cookie → 遗留 `X-Admin-Token`/`?admin=` → 遗留 `?access=`/`x-access-token`
  → 匿名。主体 = `admin`（管理，含遗留管理 token）/ `user`（登录用户）/ `code`
  （访问码持有者）/ `anon`（仅 `allow_anonymous=true`）/ 无（拒绝）。会话可见性
  按桶（§6）：admin 全见；`shared` 桶对所有查看级主体可见（保留「访问码=共享会话」
  遗留语义）；`user` 桶仅属主+admin 可见；`code` 桶仅该码持有者+admin 可见。
  会话级端点（详情/改/删/删记录/chat/cancel）在此之上做 **IDOR** 校验：不可见 =
  404（不泄露存在性）；写操作还需「属主（user 私有桶）」或 admin，否则 401。
- **P3 cookie 会话**：`POST /api/auth/login`（用户名+密码，防枚举恒定时间比对）/
  `POST /api/auth/access-code`（访问码，无匿名捷径）→ 下发 `ea_sid` cookie
  （HttpOnly，SameSite=Lax，Path=/，12h），落 DB `auth_sessions` 表（token 哈希、
  可吊销、重启存活）；`GET /api/auth/me` 查看当前主体（匿名环境无凭证 =
  `anonymous:true`）；`POST /api/auth/logout` 吊销。用户创建/修改**仅管理**
  （`/api/admin/users`；守护「不能停用/降级最后一个 active 管理员」；停用即吊销
  该用户全部 cookie 会话）。访问码失效/过期时其 cookie 会话一并吊销。
- **P3 审计**：管理操作（bootstrap/登录、用户 CRUD、智能体 CRUD、访问码失效等）
  写 `audit_logs` 表（actor/action/目标/详情 JSON/IP）；`GET /api/admin/audit`
  （管理级，limit/offset 分页，默认 100 上限 500）。

| 端点 | 权限 |
|---|---|
| GET /api/health、GET /api/status | 公开 |
| POST /api/admin/login、POST /api/access/login | 公开（限流） |

| GET/POST /api/admin/users、PATCH /api/admin/users/:id（用户仅管理创建；停用/降级最后 active admin 被拒） | 管理 |
| GET/POST /api/admin/agents、PATCH /api/admin/agents/:code（每智能体一个协议，存 `agent_configs`；协议/配置变更清空该智能体会话后端会话 ID） | 管理 |

| POST /api/asr/test（ASR 服务测试连接） | 管理 |
| POST /api/push | 公开（凭证 = 会话推送 token，48 位高熵随机值，持有即授权；**无需访问码**，码失效/换码不影响推送） |
| POST /api/audio/stream（`X-Audio-Token` + `X-Device-Name` 头，长连接 chunked 音频流；EchoScribe 持续推流） | 公开（凭证 = 会话推送 token，与 /api/push 同级；会话须 `audio_remote.enabled`，否则 403） |

防泄漏：SSE 广播与非管理视图**剥离会话 token 与 protocol_config**（推送令牌与
会话级协议覆盖仅管理端 `GET /api/sessions`/会话详情可见）；`config` 广播为脱敏
配置（api_key（含 asr.api_key）/管理密码不出现）。
**SSE 按主体作用域投递（P3）**：带 `session_id` 的事件（qa_start/delta/done/
record_removed/session_reset/音频事件等）仅投递给对该会话可见的连接——**绝不把
一个用户私有桶的问答广播给其他主体**；`sessions` 事件逐连接按主体/作用域生成
载荷（token 从不进 SSE）；QA 事件自动补 `agent_id`（多智能体前端路由）。

前端：右上角「会话设置 / ⚙ 设置」**默认隐藏**；URL 加 `/admin` + 管理密码登录后显示
（管理功能仅 /admin 路由可用）。关闭匿名访问时，应用入口显示访问码输入页。
鉴权 token 存 localStorage（带过期时间）。
/admin 路由的查看级请求（含 SSE）经 `?access=` **优先携带管理 token**
（服务端 viewerOk 管理/访问 token 皆认）：避免服务端重启后本地未过期但
服务端已失效的 access token 抢先发送 → 查看级调用全部 403 → 误弹管理员登录。

启动时序：页面初始带 `booting` 类（首页隐藏），`/api/status` 检查完成前不显示任何
内容，避免「先闪一下首页再弹门禁」；无需门禁则解锁进应用，需要门禁则停在
登录页（登录成功才解锁首页）。
- 访问码/管理 token **运行中失效**（到期、被一键失效、服务端重启）：SSE 断流后
  EventSource 拿不到 403 状态，前端用一次带鉴权的探测请求（管理路由探
  `/api/config`，否则探 `/api/sessions?access=`）区分「token 失效」与「网络抖动」；
  确认失效 → 清除本地 token、停掉 SSE 无谓重连、弹出对应门禁要求重新输入
  （网络错误不弹门禁，继续自动重连）。

设置抽屉（「⚙ 设置」，宽 880px、内容居中）顶部为**单行分段标签**（药丸样式）：
**协议配置**组（知识引擎 / 编排引擎 / OpenAI / 通用，顺序即默认展示优先级，首项默认激活）、
**语音输入**组（语音；ASR 服务配置 + 「测试连接」，见 §7 语音输入）与
**安全配置**组（安全），组标签为**左侧强调色竖条的分区标记**（与可点药丸 tab 明确区分），
组间细线分隔。安全页为卡片式布局：① 匿名访问开关（**切换即时生效**，独立于「保存配置」）；② 访问码（列表：
码值 + 状态徽标 + 剩余时长 + 复制/延期/失效；生成表单带「码 / 有效时长（小时）/
数量（个）」字段标签 + 清理已过期）；③ 管理密码（独立「设置/修改管理密码」
按钮，即时保存，不走「保存配置」）。抽屉通用交互：**点击抽屉外部自动收起**（点击来自打开按钮的不处理；「会话设置」抽屉对会话列表项点击视为相关区域，不收起）；
「会话设置」抽屉在打开状态下**跟随左侧会话切换同步刷新内容**（名称/协议/
token/会话级协议配置/EchoScribe 片段即时更新为新会话）；**会话级协议配置**按当前

「正在加载设置…」，保存按钮禁用），`/api/config` 拉取完成才揭示表单，避免
手快时看到空白表单（SSE 推送的配置变更刷新表单时不加遮罩，防闪烁）。

### 3.5 电脑输出音频流（EchoScribe「持续推流」）

EchoScribe 桌面端捕获 **WASAPI 输出设备回环**（如 ToDesk 虚拟声卡）的音频，经既有
HTTPS sidecar（**不新增端口**）以长连接 chunked POST 持续推给 EchoAnswer；本服务把
音频按「会话 × 设备」缓存进环形缓冲，Web 端可随时「识别最近 N 秒 → ASR →
自动作为提问」（问答 source 记为 `remote_audio`，卡片显示「🎧 电脑音频」徽标）。

- **帧协议**（EchoScribe → 服务器，`POST /api/audio/stream`）：
  请求头 `X-Audio-Token`（会话推送 token）+ `X-Device-Name`（URL 编码的
  「6位设备码 · 端点名称」，如 `A1B2C3 · 扬声器 (ToDesk Virtual Audio)`；
  新版 EchoScribe 发送，设备码 = 其 sha1(主机名|音频源|端点ID)[:6]，稳定且
  跨机器唯一——多台机器用同名虚拟声卡推流时按码区分来源；服务器原样记录
  用于「会话 × 设备」隔离与前端展示；旧版 EchoScribe 可能发设备序号，前端
  对纯数字编码显示「（旧版序号编码）」提示）；
  请求体为连续帧 `[u32BE len][Deflate(PCM16LE 16kHz 单声道)]`，一帧 = 200ms =
  6400B PCM。Deflate 无损压缩；采样格式与麦克风语音输入相同（16-bit/16kHz），
  「高保真」= 不降采样 + 无损压缩。
- **鉴权与门控**：token 缺失/未知 → 401；会话 `audio_remote.enabled !== true` →
  403（响应阶段拒绝，不消费体）；同会话同设备已有流 → 409。
- **服务器处理**：前置校验错误（401/403/409）仅凭请求头即时响应；成功路径在
  **收完整体后**回 `200 {ok, stream:"stopped", session_id, device, bytes, frames}`
  ——nginx（`proxy_request_buffering off`）在上游响应完成时会截断客户端未发完的
  body，先回 200 会导致后续帧全部丢失（实测，见 doc/03 §8），故 200 延迟到流
  结束并携带统计摘要；流进行中的实时反馈走 SSE `audio_stream` 事件；帧解析器
  违例（len>1MB / PCM 奇数字节 / Deflate 失败）→ 400 + **只断开该设备流**，不
  影响同会话其他设备；60s 无帧自动清理该设备流；每会话最多 8 个设备流；会话
  删除即清理其全部流。
- **环形缓冲**：每设备保留最近 `audio_stream.max_buffer_s`（默认 120s，
  32KB/s ≈ 3.8MB/设备），字节上限 + 时间截止双淘汰；仅存内存，不落盘。
- **识别并提问**（`POST /api/audio/capture`）：body `{token, device?, seconds?}`；
  device 缺省取 `audio_remote.preferred_device`（失效时：唯一设备流自动用之，
  多设备 → 400 提示指定，无设备 → 409）；seconds 缺省 `default_capture_s`（30），
  越界 `min/max_capture_s`（5/60）→ 400；设备最近 5s 无帧 → 409；ASR 未配置 →
  400；识别为空 → 422；ASR 失败 → 502。成功 → `QaRunner.start(source:"remote_audio")`，
  响应 `{ok, text, qa_id, session_id, device, duration_s}`，前端 toast 提示。
- **实时识别**（提问框「音频」按钮，对齐 EchoScribe 交互）：
  `POST /api/audio/listen`（body `{token, device?}`）开始——服务端每 2.5s 把「开始→当前」
  全段重提一次（对齐 EchoScribe「段进行中」中间识别语义；在途不排队），SSE
  `audio_listen {session_id, device, state, text, elapsed_s}` 广播；state =
  `partial`（中间识别，text = 当前全段识别结果）/ `stopped`（停止定稿或满 120s
  自动停）/ `cancelled`（取消，text 清空）/ `stream_stopped`（推流断开自动停，
  携带已识别文本）。`POST /api/audio/listen/stop`（定稿：全段最后一次识别，响应
  `{ok, text, elapsed_s}`）；`POST /api/audio/listen/cancel`（丢弃）。同设备已有
  任务 → 409；设备未接收 → 409；ASR 未配置 → 400；连续 3 次识别失败/无声自动停
  （stream_stopped）。会话删除 / 设备流结束即清理任务；前端定稿语义与「语音」一致
  （勾选「识别后自动发送」→ 直接提问，否则填入输入框）。`/api/audio/capture`
  保留（API 层一键截取+自动提问）。
- **nginx**（tls sidecar）：该路径专用 location 关闭请求缓冲
  （`proxy_request_buffering off` + `client_max_body_size 0` + 读写超时 3600s）；
  注意该指令下 upstream 一旦响应完成，nginx 即截断客户端未发完的 body，故服务器
  侧必须「收完整体再响应」（见上条），详见 doc/03 §8。

## 4. 问答执行流程（QaRunner）

```
start(session, question, opts)
  ├─ 解析协议配置：全局 protocols[协议] × 会话 protocol_config（会话非空值优先）
  │   （配置/协议变更时自动重置后端会话：见下方「后端会话状态失效」）
  ├─ 协议前置校验（dify 缺 api_key / ragflow 缺 chat_id / generic 模板非法 → QaError → 4xx；按合并值校验）
  ├─ 组装上下文：continue_session 且上次有答案 → 附最近识别内容/答案摘要
  ├─ 广播 qa_start {session_id, id, source, protocol, question}
  └─ _execute()
       ├─ fetch 流式读取（AbortController 取消；10s 连接 / 60s 块间空闲）
       ├─ 按协议解析增量 → record.answer 累积 → 广播 delta
       ├─ 完成/失败 → record.ok/detail + finished_at → 广播 done（含 duration_s）
       └─ history.unshift(record)（cap 100）→ 持久化 → 广播 sessions
```

统一语义（与 EchoScribe 一致）：

**后端会话状态失效（自动重置）**：会话的 `dify_conversation_id` /
`ragflow_session_id` 属于「当时的生效配置」。以下变更会把已保存的后端会话 ID
清空（下次提问按新配置重建）：会话 PUT 后该协议生效的 url/api_key/chat_id
（ragflow）或 url/api_key（dify）变化、会话协议切换；全局 PUT /api/config 后
回退全局的会话（对应字段留空）生效值变化（响应含 `invalidated_sessions` 计数）。
不重置时 RAGFlow 会拒绝：`Session does not belong to this chat!`（空回答）。

- 非 2xx → `请求失败: 状态码 + 响应体截断 200 字符`；
- SSE 非法 JSON → 「SSE 解析失败」（已流出内容保留）；
- 取消 → 保留部分答案，detail 「已取消（…）」；
- 空回答 → 「完成（空回答）」；
- 手动重置（`POST /api/sessions/:id/reset` / 全量 `/api/session/reset`）：**先取消
  在途问答**（记录转「已取消」）再清空后端会话 ID，防止在途流稍后经 onMeta
  把旧会话 ID 写回、抵消重置（表现为「重置后会话仍带旧上下文」）；历史保留。

| 协议 | 请求 | 响应解析 | 会话续接 |
|---|---|---|---|
| openai | POST 完整 url，chat completions `{messages, stream:true, model?}`，Bearer 可空；上下文→system 消息 | SSE `choices[0].delta.content`（兼容 `choices[0].text`），`[DONE]` 结束 | 无状态（每次携带 system 上下文） |

## 6. 存储设计（SQLite）

- 库文件：`data/echoanswer.db`（`ECHOANSWER_DATA_DIR` 可改目录）；Node 内置
  `node:sqlite`（DatabaseSync，同步 API），`PRAGMA journal_mode = WAL`。
- **Schema 版本**：`PRAGMA user_version = 2`（P1 数据层升级；v1 旧库首启自动
  迁移，见下方迁移链；旧名 `qa-mini.db` 先重命名为 `echoanswer.db`）。
- v2 表结构：

```sql
sessions(id PK, name, token UNIQUE, protocol, continue_session, protocol_config,
         audio_remote, dify_conversation_id, ragflow_session_id,
         user_id, agent_id, access_mode, access_code_id,
         created_at, updated_at)
records(seq PK AUTOINCREMENT, session_id, id, question, answer,
        protocol, protocol_name, source, started_at, finished_at, ok, detail,
        UNIQUE(session_id, id))
users(id PK, username UNIQUE(NOCASE), password_hash, display_name, role, status,
      created_at, updated_at, last_login_at)
agents(id PK, code UNIQUE, name, description, icon, enabled, sort, prompt,
       created_at, updated_at)          -- 每智能体一个协议：协议与配置在 agent_configs
agent_configs(agent_id PK→agents.id, protocol, config_json,
              created_at, updated_at)
protocol_defaults(name PK, config_json, updated_at)
system_configs(key PK, value_json, updated_at)
access_codes(id PK, code UNIQUE, agent_id→agents.id, status, created_at,
             expires_at, created_by)
auth_sessions(id PK, token_hash UNIQUE, principal_type, user_id→users.id,
              access_code_id→access_codes.id, ip, user_agent,
              created_at, expires_at, revoked_at)      -- P3 cookie 会话（可吊销）
audit_logs(id PK AUTOINCREMENT, actor_type, actor_id, action, target_type,
           target_id, detail_json, ip, created_at)     -- P3 管理操作审计
-- 索引: records(session_id,seq), sessions(user_id), sessions(access_code_id,agent_id),
--       auth_sessions(user_id), auth_sessions(access_code_id), audit_logs(created_at)
```

- **桶归属（P3 作用域）**：`access_mode` + `user_id`/`access_code_id` + `agent_id`
  构成会话桶——`user` 用户私有桶（`(user_id, agent_id)`，属主+管理可见）/ `code`
  访问码桶（`(access_code_id, agent_id)`，该码持有者+管理可见）/ `shared` 共享桶
  （存量会话 + 管理/匿名创建；所有查看级主体可见，保留「访问码=共享会话」遗留
  语义）。P3 首启 `store.migrateLegacyToShared()` 一次性把存量 `access_mode='user'`
  行回填为 `shared`（system_configs 标记，幂等）。`ANON` = 匿名共享桶特殊码
  （非 6 位数字，登录端点不可用，仅归属语义）。
- **写入策略（P2 增量）**：`V2SessionManager.syncAll()` 与 DB 逐行 diff
  （name/protocol/protocol_config/audio_remote/token/后端会话 ID/updated_at）+
  历史增量（appendRecord/removeRecord），只写差异、**不做整表重写**；v1 的 `pos`
  列移除（排序统一 `updated_at` 倒序）。历史 100 条上限语义不变（超限淘汰最旧，
  records 同步删除）。
- **v1→v2 迁移链**（自动、幂等、单事务，详见 doc/02 §3）：
  1. 旧名库 `qa-mini.db` 重命名为 `echoanswer.db`（含 -wal/-shm）；
  2. v1 旧库升级前自动备份 → `data/backup/echoanswer.db.bak-<时间戳>`；
  3. 单事务：v1 表 → v2 列 + 新表（users/agents/agent_configs/protocol_defaults/
     system_configs/access_codes/auth_sessions/audit_logs），`user_version` → 2；
  4. 播种：admin 用户（初始密码取 `ECHOANSWER_ADMIN_PASSWORD` 或 config
     `security.admin_password`，scrypt 哈希）、agent `industry-brain`、协议默认值、
     系统配置、访问码（allow_anonymous 时含 ANON）；
  5. 存量会话归属回填：user_id=管理员（未建时留空，首次 admin 初始化补回填）、
     agent_id=industry-brain、access_mode='user'（P1）；P3 首启再由
     `migrateLegacyToShared()` 一次性回填为 'shared'（幂等）；
  6. config.json `security.admin_password` 明文清空（先备份
     `config.json.bak-<时间戳>`，密码已哈希入库，DB 为权威）。
- **旧兼容**：`lib/config.js` 的 `loadSessions/saveSessions` 保留（供单测直调）；
  启动期「sessions.json 一次性导入 + config.push 默认会话」逻辑迁至
  `server/services/session_service.js`，行为不变（仅库空时发生）。
- 生成时长：completed 记录带 `duration_s`（秒，1 位小数，服务端
  `finished_at - started_at`）；`/api/history`、`GET /api/sessions/:id` 的
  history/running、SSE `done` 事件均携带。
- 测试隔离：`ECHOANSWER_DATA_DIR` 指向临时目录。

## 9. 安全与边界

- 定位：**局域网自用 + 多用户隔离（P3）**。会话按桶隔离（user 私有 / code /
  shared），会话级端点 IDOR 校验（不可见 = 404，写他人桶 = 401），SSE 按主体
  作用域投递（一个用户的私有问答绝不广播给其他主体）；`/api/push` 与音频推流
  保持公开（凭证 = 会话推送 token）。暴露公网必须加反向代理鉴权（见部署文档）。
- 密钥仅存本地 config.json 与 data/ 库；请勿提交公开仓库。
- **cookie 会话（P3）**：`ea_sid` HttpOnly + SameSite=Lax + Path=/（12h）；token
  哈希存 `auth_sessions`（可吊销：登出/停用用户/失效访问码即吊销对应会话）；
  登录限流 10 次失败/10 分钟/IP，密码/码比对恒定时间（防枚举与时序侧信道）。
- **审计（P3）**：管理操作（bootstrap/登录、用户/智能体 CRUD、访问码失效等）
  全部留痕 `audit_logs`（actor/action/目标/详情/IP），`GET /api/admin/audit` 可查。
- 前端 XSS 防护：答案渲染前整体 HTML 转义，白名单标签重建。
- 请求体上限 2MB；超时双保险（连接 10s / 块间 60s）。
- 音频流例外：`POST /api/audio/stream` 为长连接推流，**不适用 2MB 请求体上限**；
  其安全边界 = 会话推送 token（同 /api/push）+ 会话级 `audio_remote.enabled`
  门控 + 每设备环形缓冲上限（默认 120s ≈ 3.8MB）+ 每会话 8 设备上限 +
  60s 空闲自动清理 + 帧协议违例断流。token 泄露风险面与推送 token 相同
  （48 位高熵随机，仅管理端可见）。

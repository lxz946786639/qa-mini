# QA Mini 项目设计文档

> 版本：1.0 ｜ 适用代码：本仓库当前版本（零依赖 Node.js + 原生前端）
> 关联文档：[02-配置说明](./02-配置说明.md) ｜ [03-部署说明](./03-部署说明.md) ｜ [04-101服务器部署说明](./04-101服务器部署说明.md)

## 1. 项目定位

QA Mini 是一个 **Web 端语音问答展示** 服务：接收 asr-tool（asr-live，
dev 分支）**推送模式** 发来的语音识别文本，以该文本为提问，调用四种问答协议之一
（openai / dify / generic / ragflow），在浏览器中 **实时流式** 展示 Markdown 答案。

核心设计目标：

| 目标 | 方案 |
|---|---|
| 零依赖 | Node 内置模块（http / fs / crypto / node:sqlite）+ 原生 JS 前端，无 npm 包、无构建步骤 |
| 协议行为一致 | 四种协议的请求/解析/容错逻辑 1:1 移植自 asr-tool |
| 多会话隔离 | 每会话独立 token / 会话ID / 协议 / 后端会话状态 / 历史 |
| 多端实时同步 | 单一 SSE 广播通道，事件均带 session_id |
| 开箱即用 | 内置默认配置（本机 RAGFlow），首次启动自动建库、自动建默认会话 |

## 3. 会话模型（多会话核心）

### 3.1 数据模型

每会话（sessions 表一行 + 内存对象）：

| 字段 | 说明 |
|---|---|
| id | 8 位 hex，创建时生成，**不可变**（asr-tool body 里引用它） |
| name | 显示名（可改） |
| token | `kaasr_` + 48 hex 推送令牌（可重生成，旧 token 立即失效） |
| protocol | `ragflow` / `openai` / `dify` / `generic`（会话级选择） |
| continue_session | 是否续接后端会话（语音追问带上下文） |
| dify_conversation_id | Dify 多轮 conversation_id（重置时清空） |
| ragflow_session_id | RAGFlow 会话 ID（无则先建会话；重置时清空） |
| created_at / updated_at | ISO 时间（updated_at 在提问/完成/重置/删记录时刷新，即「最新对话时间」） |
| history | 最近 **100** 条问答（新→旧环形缓冲，records 表持久化） |

不变式：

- **至少 1 个会话**：删除最后一个会话时自动补建「默认会话」。
- 首次启动且库为空：迁移 config.json `push.token` 创建「默认会话」
  （旧 asr-tool 配置零改动）。
- 再之前（无库）：若存在旧 `data/sessions.json`，一次性导入 SQLite 并归档为
  `sessions.json.bak-<时间戳>`。
- **列表按最新对话时间倒序**：`GET /api/sessions` 与 SSE `sessions` 广播均按
  `updated_at` 降序（同时间按创建时间降序）——最近对话的会话排最前。

### 3.2 定位与校验（/api/push）

1. `token` → 会话（未知 → **401**）；
2. 请求体带 `session_id` 时必须等于该会话 id（否则 **400**，防 token 复制错配）；
3. 只带 token（不带 session_id）兼容旧行为；
4. `text` 非空（否则 400）。

### 3.3 多浏览器同步

前端无轮询：EventSource 连 `/api/events`。服务器对每个客户端广播全部 QA 事件
（均带 `session_id`）；前端只渲染当前会话的 qa_start/delta/done，其余事件用于
刷新侧栏（sessions）与移除卡片（record_removed）等。切会话时
GET /api/sessions/:id 拉历史 + 在途问答，重建卡片。

### 3.4 访问控制（管理密码 + 访问码）

两级权限，均可选（默认 = 旧行为全开放）：

| 级别 | 开关 | 效果 |
|---|---|---|
| 管理 | `security.admin_password` | 空 = 管理未启用（管理接口不鉴权，旧行为）；设置后管理接口强制登录鉴权 |
| 访问 | `security.allow_anonymous` | true = 匿名可看可问（旧行为）；false = 需 6 位访问码进入 |

- **管理密码**：首次 `POST /api/admin/login`（或浏览器 `/admin` 登录页）输入的密码
  即**初始化**（4-64 位）；之后校验登录，可在设置中修改（`security.admin_password`）。
  管理 token 有效期 12h，仅存内存（重启需重新登录）。
- **访问码**：6 位数字，可自定义或随机生成；**可生成多个，每个码独立有效时长**
  （默认 8h，0.5-720h；批量随机 1-10 个）；存 `security.access_codes`（config.json
  持久化）；支持**单个延期**（renew，到期时间后移）、**一键失效**（删除 + 已发 token
  立即吊销）、**清理全部过期码**。访问 token 有效 24h（且不超过码自身有效期）。
- **登录限流**：10 次失败/10 分钟/IP → 429；密码/码比对走 timingSafeEqual（防时序侧信道）。

端点权限（管理 = 管理 token；查看 = 匿名或访问 token；公开 = 无需鉴权）：

| 端点 | 权限 |
|---|---|
| GET /api/health、GET /api/status | 公开 |
| POST /api/admin/login、POST /api/access/login | 公开（限流） |
| POST /api/admin/access-codes（{code?, hours?, count?}）、DELETE /api/admin/access-codes/:code、POST …/:code/renew、DELETE …/expired | 管理 |
| GET/PUT /api/config | 管理 |
| POST/PUT/DELETE /api/sessions…（含 reset、删记录）、POST /api/session/reset | 管理 |
| GET /api/sessions、GET /api/sessions/:id、GET /api/history、POST /api/chat、POST /api/cancel | 查看 |
| POST /api/push | 查看（开启访问码后请求体需携带 `access` 访问 token） |
| GET /api/events（SSE） | 查看（EventSource 无法带请求头 → token 走 `?access=` 查询参数） |

防泄漏：SSE 广播与非管理视图**剥离会话 token**（推送令牌仅管理端
`GET /api/sessions`/会话详情可见）；`config` 广播为脱敏配置（api_key/管理密码不出现）。

前端：右上角「会话设置 / ⚙ 设置」**默认隐藏**；URL 加 `/admin` + 管理密码登录后显示
（管理功能仅 /admin 路由可用）。关闭匿名访问时，应用入口显示访问码输入页。
鉴权 token 存 localStorage（带过期时间）。

设置抽屉（「⚙ 设置」，宽 880px、内容居中）顶部为**单行分段标签**（药丸样式）：
**协议配置**组（OpenAI / Dify / 通用 / RAGFlow）与 **安全配置**组（🔒 安全），
组间细线分隔。安全页为卡片式布局：① 匿名访问开关（**切换即时生效**，独立于「保存配置」）；② 访问码（列表：
码值 + 状态徽标 + 剩余时长 + 复制/延期/失效；生成表单带「码 / 有效时长（小时）/
数量（个）」字段标签 + 清理已过期）；③ 管理密码（独立「设置/修改管理密码」
按钮，即时保存，不走「保存配置」）。

## 4. 问答执行流程（QaRunner）

```
start(session, question, opts)
  ├─ 协议前置校验（dify 缺 api_key / ragflow 缺 chat_id / generic 模板非法 → QaError → 4xx）
  ├─ 组装上下文：continue_session 且上次有答案 → 附最近识别内容/答案摘要
  ├─ 广播 qa_start {session_id, id, source, protocol, question}
  └─ _execute()
       ├─ fetch 流式读取（AbortController 取消；10s 连接 / 60s 块间空闲）
       ├─ 按协议解析增量 → record.answer 累积 → 广播 delta
       ├─ 完成/失败 → record.ok/detail + finished_at → 广播 done（含 duration_s）
       └─ history.unshift(record)（cap 100）→ 持久化 → 广播 sessions
```

统一语义（与 asr-tool 一致）：

- 非 2xx → `请求失败: 状态码 + 响应体截断 200 字符`；
- SSE 非法 JSON → 「SSE 解析失败」（已流出内容保留）；
- 取消 → 保留部分答案，detail 「已取消（…）」；
- 空回答 → 「完成（空回答）」。

## 5. 四种协议客户端设计

| 协议 | 请求 | 响应解析 | 会话续接 |
|---|---|---|---|
| openai | POST 完整 url，chat completions `{messages, stream:true, model?}`，Bearer 可空；上下文→system 消息 | SSE `choices[0].delta.content`（兼容 `choices[0].text`），`[DONE]` 结束 | 无状态（每次携带 system 上下文） |
| dify | POST `{基址}/chat-messages`（自动补路径）`{inputs:{}, query, response_mode:"streaming", user, conversation_id?}`；上下文拼进 query | 按 event 分派：`message`→增量+捕获 conversation_id；`message_end` 结束；`error` 抛错 | conversation_id |
| generic | 模板 `{question}`/`{context}` 递归替换 + 顶层注入；最小模板 `{}` 即可 | 自动识别 SSE / 单 JSON / 纯文本；答案字段多级回退（delta.content → text → data.* → 顶层） | 无 |
| ragflow | 新路径 `/chat/completions`（404 回退一次 `/chats/{chat_id}/completions`）；无会话先 `POST /chats/{chat_id}/sessions`（RAGFlow ≤v0.24 必需） | 信封 `{code,message,data}`：`data==true` 结束；code≠0 流内报错；思考区跳过；delta/cumulative 自动识别（LCP 差分）；`##0$$` 标记；reference 去重脚注 | ragflow_session_id |

细节与已知限制见 README「已知限制」（RAGFlow legacy think 标签、LCP 极端差分、
Dify Human Input 挂起）。

## 6. 存储设计（SQLite）

- 库文件：`data/qa-mini.db`（`QA_MINI_DATA_DIR` 可改目录）；Node 内置
  `node:sqlite`（DatabaseSync，同步 API），`PRAGMA journal_mode = WAL`。
- 表：

```sql
sessions(id PK, name, token, protocol, continue_session,
         dify_conversation_id, ragflow_session_id, created_at, updated_at, pos)
records(seq PK AUTOINCREMENT, session_id, id, question, answer,
        protocol, protocol_name, source, started_at, finished_at, ok, detail,
        UNIQUE(session_id, id))
-- 索引: records(session_id, seq)
```

- 写入策略：`saveAll` 事务内整表重写（会话 + 历史，数据量 ≤ 会话数×100，
  毫秒级；实现最简且最稳）。records 的 `seq` 保证历史顺序与内存一致（新→旧
  读取 = `ORDER BY seq DESC`）。
- 迁移链：`sessions.json`（旧）→ 一次性导入 → 归档 .bak；`config.push` →
  默认会话 token。旧库首次启动自动 `ALTER TABLE records ADD COLUMN finished_at`
  （生成时长统计，老记录该列为空 → duration_s 省略）。
- 生成时长：completed 记录带 `duration_s`（秒，1 位小数，服务端
  `finished_at - started_at`）；`/api/history`、`GET /api/sessions/:id` 的
  history/running、SSE `done` 事件均携带。
- 测试隔离：`QA_MINI_DATA_DIR` 指向临时目录。

## 7. 前端设计（public/）

- 无框架无构建：单页 `index.html` + `app.js` + `style.css`，服务器按路径
  静态服务（每请求读盘，改文件即生效，无需重启）。
- 状态：`sessions` Map（侧栏）、`currentSid`、`sessionCards` Map<sid, Map<qaId, state>>
  （卡片 DOM 引用：answerEl/statusEl/按钮）、`pendingLocals`（乐观本地卡）、
  `lastActive`。
- 渲染：内联 Markdown 渲染器（**先 HTML 转义后渲染**，防 XSS；支持代码块/加粗/
  斜体/链接/标题/列表/引用）；delta 高频更新走 rAF 合帧。
- 滚动跟随：滚动容器为 `main#chat`（滚动行为全部由 JS 显式指定，不用 CSS
  scroll-behavior）；**打开/切换会话时即时落在内容最新位置**（即时落底 +
  markdown rAF 渲染后二次校正，不用平滑动画避免被高度增长打断）；流式输出中仅
  当用户贴近底部（<140px）时即时跟随（不打断上滑阅读）；新提问/「↓ 最新」浮钮
  点击走平滑滚动。
- 卡片：问题块（「问」标签 + 左侧高亮条）/ 答案块（「答」标签 + 底部状态行）；
  来源徽标（🎤 语音推送 / 💬 网页）、协议、时间；空会话显示默认提示（标题 +
  提问/推送指引 + 当前协议与会话ID，切会话时动态刷新）；一键复制（问题/答案）、
  ✕ 停止、🗑 删记录。
- 生成时长：答案状态行显示耗时（「✔ 完成（732 字符 · 12.5s）」，服务端
  started/finished 计算，历史卡片同样显示）；生成中状态行实时计时
  「生成中… 3.2s」。
- 交互特性（均 localStorage 记忆）：字号（默认/大/自定义 12–28px）、
  主题（深色/浅色，head 内联脚本防闪烁）、侧栏（桌面收起记忆 / 平板自动收起 /
  手机抽屉）、保存即收起抽屉。
- 响应式断点：>1024 桌面；≤1024 平板（侧栏默认收起，可展开）；≤720 手机
  （会话列表左侧滑出抽屉、100dvh、iOS 安全区、触控优化）；≤400 小屏。
- **PWA**：`manifest.webmanifest`（standalone、主题色、any + maskable 图标，
  图标由纯 Node 脚本程序化生成 PNG，零依赖）+ service worker（`sw.js`，
  缓存 `qa-mini-v*`）：页面导航网络优先/离线回退缓存首页；静态资源缓存优先
  后台回填；**`/api/*`（含 SSE）直通网络永不缓存**。静态资源更新需递增
  `CACHE` 版本号；theme-color 随主题切换动态更新。

## 9. 安全与边界

- 定位：**局域网自用**。/api/config、/api/sessions 无鉴权；暴露公网必须加
  反向代理鉴权（见部署文档）。
- 密钥仅存本地 config.json 与 data/ 库；请勿提交公开仓库。
- 前端 XSS 防护：答案渲染前整体 HTML 转义，白名单标签重建。
- 请求体上限 2MB；超时双保险（连接 10s / 块间 60s）。

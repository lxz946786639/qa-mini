## 3. 常用运维命令

所有 compose 命令在 `/mnt/disk1/docker-data/qa-mini/docker` 下执行：

```bash
cd /mnt/disk1/docker-data/qa-mini/docker

docker compose ps                     # 状态（应为 Up (healthy)）
docker compose --profile tls ps       # 含 https sidecar（echoanswer-tls）
docker compose logs -f --tail 100     # 日志
docker compose restart                # 重启
docker compose down                   # 停止（数据保留）

docker compose exec EchoAnswer node -e "…"  # 容器内执行（如查库）
```

## 4. 镜像构建的特殊情况（重要）

101 的 Docker 配置了国内镜像源（daocloud/1ms/xuanyuan），其中 daocloud 对匿名
拉取返回 **401**，直接 `docker compose up -d --build` 失败。本机（Windows +
Docker Desktop）网络同样无法直连 Docker Hub，但可经 `docker.1ms.run` 拉取基础镜像。

**因此本部署采用「构建机出镜像 → 传输 → 加载」流程**（升级时也按此流程）：

```bash
# ① 构建机（有 Docker Desktop 的开发机）
docker pull docker.1ms.run/library/node:24-alpine   # 首次；已有本地 node:24-alpine 可跳过
docker tag  docker.1ms.run/library/node:24-alpine node:24-alpine
cd <EchoAnswer 项目根>
docker build -f docker/Dockerfile -t echoanswer:latest .
docker save echoanswer:latest -o /tmp/EchoAnswer.tar

# ② 传输到 101（scp / sftp / 任意方式）
scp /tmp/EchoAnswer.tar root@172.16.30.101:/tmp/

# ③ 101 上加载并启动
docker load -i /tmp/EchoAnswer.tar && rm -f /tmp/EchoAnswer.tar
cd /mnt/disk1/docker-data/qa-mini/docker
docker compose up -d          # 无 --build，直接用已加载的 echoanswer:latest
```

镜像含基础镜像层，tar 约 165MB。

> **v58 改名迁移**（一次性，2026-10-05 已执行）：compose 服务名 `qa-mini` / `qa-mini-tls` →
> `echoanswer` / `echoanswer-tls`（镜像 `echoanswer:latest`）；数据目录 `qa-mini.db` 首次启动
> 自动重命名 `echoanswer.db`（27 会话保留）；tls 自签证书以 CN=echoanswer 重新生成（https
> 端需重新信任自签证书一次）；宿主目录 `/mnt/disk1/docker-data/qa-mini` 保持不变（数据挂载路径）。

## 7. 升级流程（代码更新后）

1. 同步新代码到 `/mnt/disk1/docker-data/qa-mini`（覆盖 server.js/lib/public 等）；
2. 按 §4 流程在构建机重新 build + save + scp + load；
3. `cd …/docker && docker compose up -d`（换新镜像）；
4. `docker compose ps` + `curl …/api/health` 验证。

数据（data/ 卷）不受升级影响。
